## 发现的业务缺陷（3 个，均为断言保留"正确期望"的预期失败）

### Bug 1：加购不校验数量 ≤ 库存（FmCartItemServiceImpl.addToCart）
- 用例：`TC_CART_ADD_006`（`cases/single_cases/tc_cart_add_006.yaml`）
- 前置：商品库存设 50，购物车数量 100
- 期望：`203002 库存不足`；实测：`100000 成功`
- 结论：加购只校验 `stock>0`，与需求"库存不足(203002)"不一致

### Bug 2：更新购物车数量不校验库存（FmCartItemServiceImpl.updateCartItem）
- 用例：`TC_CART_UPDATE_004`（`cases/single_cases/tc_cart_update_004.yaml`）
- 前置：商品库存设 50，把购物车项数量改为 100
- 期望：`203002 库存不足`；实测：`100000 成功`
- 结论：与需求及加购语义不一致，属于缺陷

### Bug 3：订单详情缺少属主校验（FmOrderServiceImpl.getOrderDetail）
- 用例：`flow_cross_user_detail.yaml`（`cases/biz_flows/flow_cross_user_detail.yaml`）Step02
- 场景：buyer02 登录后 `GET /api/orders/{buyer01的订单ID}`
- 期望：`200003 无权执行此操作`；实测：`100000 成功`，返回完整订单详情（含收货人、金额、明细）
- 结论：越权读取。补充：同批次的越权支付/取消/收货（`flow_cross_user_pay/cancel/receive.yaml`）均实测返回 `200003` 通过，说明操作类接口有属主校验，唯独详情接口缺失
